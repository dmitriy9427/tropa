# 02. Next.js простым языком

Next.js — это React плюс «рамка» вокруг него: маршрутизация через папки,
рендер на сервере или при сборке, оптимизация шрифтов и картинок. Если
привык к React + Vite, отличий немного, но они важные.

## Маршруты = папки (App Router)

В Vite-проекте маршруты описывают кодом (`<Route path="/trip">`). В Next —
файлами:

| Файл | Адрес |
| --- | --- |
| `src/app/page.tsx` | `/` |
| `src/app/trip/page.tsx` | `/trip/` |
| `src/app/layout.tsx` | обёртка для всех страниц |

`layout.tsx` рендерит `<html>`, `<body>`, шапку и внутрь — `{children}`,
то есть текущую страницу. При переходе между страницами layout **не
перерисовывается**: шапка остаётся, меняется только содержимое.

Особые имена файлов Next подхватывает сам: `icon.svg` станет фавиконкой,
`not-found.tsx` — страницей 404, `loading.tsx` — заглушкой при загрузке.

## Серверные и клиентские компоненты

Главная идея App Router. **По умолчанию каждый компонент — серверный.**

- **Серверный компонент** выполняется на сервере (у нас — один раз при
  `next build`). В браузер уходит готовый HTML, а сам код компонента — нет.
  В нём нельзя `useState`, `useEffect`, обработчики `onClick`, `window`.
- **Клиентский компонент** помечается строкой `'use client'` в начале файла.
  Он тоже рендерится в HTML при сборке, но его код ещё и отправляется в
  браузер, где компонент «оживает» (гидратация) и может реагировать на
  действия пользователя.

Как это разделено в «Тропе»:

| Компонент | Тип | Почему |
| --- | --- | --- |
| `app/layout.tsx`, `app/page.tsx` | серверный | разметка без состояния |
| `Header.tsx` | серверный | ссылки; внутри — клиентский `ThemeToggle` |
| `Topo.tsx` | серверный | генерирует SVG рельефа при сборке — генератор не попадает в бандл |
| `HeroPreview.tsx` | серверный | только разметка и CSS-анимации |
| `NewTripForm.tsx`, `SavedTrips.tsx` | клиентский | состояние, localStorage |
| всё в `planner/` | клиентский | перетаскивание, карта, запросы |

Серверный компонент может включать клиентский (`Header` → `ThemeToggle`),
наоборот — нельзя импортировать серверный в клиентский. Граница проходит
по директиве `'use client'`: всё, что импортирует такой файл, тоже клиентское.

Пример выигрыша — `Topo.tsx`: алгоритм marching squares считает линии
рельефа при сборке. Пользователь получает готовый `<svg>`, а ~150 строк
генератора не скачивает и не выполняет.

## Гидратация и почему важно «одинаково на сервере и в браузере»

Клиентский компонент рендерится дважды: при сборке (в HTML) и в браузере.
React сравнивает результат с HTML и, если он отличается, ругается
(«hydration mismatch») и перерисовывает кусок страницы целиком.

Чего нет при сборке: `localStorage`, текущей даты пользователя, системной
темы. Поэтому:

- **Поездки из localStorage.** Хранилище создано с `skipHydration: true` —
  при сборке оно пустое и не пытается читать localStorage. В браузере
  `useHydrateTrips()` загружает данные после монтирования, а до этого
  компонент рисует заглушку. Заглушка есть и в HTML — расхождения нет.
- **Сегодняшняя дата в форме.** Форма рисуется только после загрузки
  поездок, то есть уже в браузере, поэтому `today()` всегда браузерная.
- **Тема.** Маленький скрипт в `<head>` (`THEME_SCRIPT` в `lib/theme.ts`)
  ставит `data-theme` до первой отрисовки — страница не мигает светлым.
  У `<html>` стоит `suppressHydrationWarning`: React не считает ошибкой, что
  атрибут изменил скрипт.
- **Тема в компонентах.** `useTheme()` построен на `useSyncExternalStore`
  с отдельным «серверным» значением `null` — до гидратации компонент
  рисует нейтральное состояние.

## Статический экспорт

`next.config.ts`: `output: 'export'`. Команда `next build` кладёт в `out/`
обычные HTML, CSS и JS. Сервер Next не нужен — подойдёт GitHub Pages.

Что это ограничивает:

- **Нет динамических маршрутов с заранее неизвестными id.** `/trip/[id]`
  потребовал бы перечислить все id при сборке, а поездки создаёт
  пользователь. Поэтому одна страница `/trip/`, а какая поездка —
  в параметре `?id=`.
- **`useSearchParams` нужно оборачивать в `<Suspense>`.** При сборке адреса
  нет. Всё, что внутри `Suspense`, рендерится уже в браузере, а в HTML
  попадает `fallback`. См. `app/trip/page.tsx`.
- **Нет оптимизации картинок `next/image`.** Ей нужен сервер. Стоит
  `images: { unoptimized: true }`, а превью нужной ширины отдаёт сам
  Wikimedia Commons (`?width=160`).
- **Нет Server Actions, Route Handlers, middleware** — всё, что работает
  на сервере во время запроса.

`basePath: '/tropa'` — сайт живёт в подпапке GitHub Pages. `<Link>` и
`router.push` добавляют префикс сами, а для ссылки «поделиться» он берётся из
`process.env.NEXT_PUBLIC_BASE_PATH`.

## `next/dynamic` и `ssr: false`

Карта (`TripMap`) подключается так:

```ts
const TripMap = dynamic(() => import('./TripMap').then((m) => m.TripMap), { ssr: false })
```

- MapLibre при импорте обращается к `window` и WebGL — при сборке их нет.
- Код карты (сотни килобайт вместе с библиотекой) уходит в отдельный файл и грузится
  параллельно, не задерживая список.

## `next/font`

```ts
const display = Unbounded({ subsets: ['latin', 'cyrillic'], variable: '--font-display' })
```

Шрифт скачивается при сборке и раздаётся с нашего же адреса: в браузере нет
запроса к Google, нет «прыжка» текста при подгрузке (Next подбирает
запасной шрифт с теми же метриками). `variable` создаёт CSS-переменную —
дальше шрифт подключается в SCSS через `var(--font-display)`.

## Метаданные

`export const metadata` в `layout.tsx` и `page.tsx` — Next собирает из них
`<title>`, `<meta name="description">`, Open Graph. Шаблон
`template: '%s · Тропа'` дописывает название сайта к заголовку страницы:
у планировщика `title: 'Поездка'` → «Поездка · Тропа».

## Чем это отличается от Vite + React Router

| | Vite + React Router | Next.js (этот проект) |
| --- | --- | --- |
| Маршруты | код | папки |
| Первый HTML | пустой `<div id="root">` | готовая разметка страницы |
| Компоненты | все в браузере | серверные + клиентские |
| Шрифты | вручную | `next/font` |
| Ленивая загрузка | `React.lazy` | `next/dynamic` (+ `ssr: false`) |
