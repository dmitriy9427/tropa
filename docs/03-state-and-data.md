# 03. Состояние и данные

В приложении два вида данных, и для каждого свой инструмент.

| Данные | Чьи | Инструмент |
| --- | --- | --- |
| Поездки, места, порядок | пользователя, меняются им | **Zustand** + localStorage |
| Города, места, погода, фото | чужих сервисов, только читаем | **TanStack Query** |
| Выбранный день, вкладка, наведение | экрана, временные | `useState` в компонентах |

## Zustand: поездки

`src/store/trips.ts`. Хранилище — обычный хук:

```ts
const trip = useTrips((s) => s.trips[id])        // подписка на одну поездку
const move = useTrips((s) => s.movePlace)        // действие
```

Селектор `(s) => s.trips[id]` важен: компонент перерисуется, только когда
изменилась **эта** поездка. Если селектор каждый раз собирает новый массив
(`SavedTrips`), его оборачивают в `useShallow` — сравнение по элементам.

Действия не содержат логики, а вызывают чистые функции из `lib/trip.ts`:

```ts
movePlace: (id, placeId, to, index) => update(id, (t) => T.movePlace(t, placeId, to, index)),
```

Почему Zustand, а не Context или Redux:
- Context перерисовывает всех потребителей при любом изменении;
- Redux Toolkit для такого объёма — лишняя церемония;
- Zustand: хук без провайдера, селекторы, `persist` из коробки.

### persist и гидратация

`persist` пишет состояние в localStorage при каждом изменении и читает при
загрузке. В Next есть ловушка: при сборке localStorage нет, а если читать
его сразу в браузере, первый рендер не совпадёт с HTML (подробнее — глава 02).
Поэтому `skipHydration: true` и хук `useHydrateTrips()`.

И вторая ловушка: если вызвать действие **до** загрузки из localStorage,
`persist` сохранит пустое состояние поверх старых поездок. Поэтому форма
создания поездки появляется только после `hydrated === true`.

## TanStack Query: данные из сети

`src/lib/queries.ts`. Пример:

```ts
useQuery({
  queryKey: ['forecast', city.lat, city.lon],
  queryFn: ({ signal }) => forecast(city, signal),
  staleTime: HOUR,
})
```

Что это даёт без единой строчки своего кода:

- **Кеш по ключу.** У каждого дня поездки свой `DayHeader` с `useForecast` —
  а запрос погоды один, все получают общий результат.
- **Отмена.** Пользователь печатает «Каз…», «Казан…» — старый запрос
  отменяется через `signal` (AbortController).
- **Повторы** при сетевых ошибках, флаги `isLoading` / `isError`, `refetch()`
  для кнопки «Повторить».
- **`placeholderData: (prev) => prev`** — пока грузится новый ответ, в
  списке остаётся старый, и он не «мигает» пустотой.

Плюс собственный `useDebounced` — запрос уходит, когда пользователь сделал
паузу в 250–350 мс, а не на каждую букву.

## Откуда берутся места

**Подборка «Главное / Музеи / Парки»** — запрос SPARQL к Wikidata
(`sparqlQuery` в `lib/api.ts`): объекты в радиусе 10 км с координатами,
отфильтрованные по типу (мечеть, собор, музей, парк…) и отсортированные по
числу статей в Википедии на разных языках. У Казанского кремля их ~50, у
безымянного сквера 0 — получается честный рейтинг популярности. Заодно
приходят фото (Commons) и ссылка на статью.

**Кафе** — Overpass API (OpenStreetMap). Публичные серверы бывают
перегружены, поэтому перебираем три зеркала с таймаутом 12 секунд
(`AbortSignal.any([signal, AbortSignal.timeout(12000)])`).

**Поиск по названию** — Photon: быстрый геокодер по данным OSM с
«подтягиванием» результатов к координатам города.

## Ссылка «поделиться»

Сервера нет, поэтому поездка едет **в самой ссылке** (`lib/share.ts`):

1. Объекты превращаются в компактные массивы (`[name, kind, lat, lon, …]`),
   координаты округляются до 5 знаков (~1 м).
2. JSON сжимается `lz-string` в строку, безопасную для URL.
3. Получатель открывает `/trip/?s=…` → поездка раскодируется, получает новые
   id и сохраняется к нему. Хеш ссылки запоминается в `importedFrom`, чтобы
   повторное открытие не создавало копию.

Пример на 3 дня и 17 мест — около 2 000 символов.

## Диалоги вместо confirm()

Системные `confirm()` и `prompt()` выглядят чужеродно, блокируют вкладку и
не настраиваются. Вместо них — свой диалог (`store/dialog.ts` +
`components/DialogHost.tsx`), но вызывается так же просто:

```ts
if (await ask({ title: 'Удалить «Казань»?', confirmLabel: 'Удалить', tone: 'danger' })) remove(id)
```

`ask()` кладёт параметры в маленькое Zustand-хранилище и возвращает промис;
`DialogHost` (один на приложение, в `layout.tsx`) показывает окно и
разрешает промис ответом.

Окно — нативный `<dialog>` с `showModal()`. Это даёт без единой строчки кода:
фокус внутри окна, закрытие по Esc, затемнение фона (`::backdrop`) и
недоступность остальной страницы для скринридеров. Для опасных действий
фокус ставится на «Отмена» — случайный Enter ничего не удалит.
